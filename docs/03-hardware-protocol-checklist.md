# 硬件厂协议资料清单(发给硬件方案商的正式索取函附件)

用途:立项阶段0(第 1—2 周)向硬件厂发出的完整资料清单。**本清单未交付齐全前,不进入 App 全面研发。**
回签方式:硬件厂逐项填写"提供/不提供/替代方案",并附文档版本号与负责人。

## A. BLE 协议(必须)

| # | 项目 | 说明 |
|---|---|---|
| A1 | Service UUID | 全部服务 UUID 列表 |
| A2 | Characteristic UUID | 每个特征的 UUID |
| A3 | Read / Write / Notify 定义 | 每个特征的读写与通知属性 |
| A4 | 数据包头 | 帧头定义 |
| A5 | 命令字 | 完整命令字表 |
| A6 | 长度字段 | 长度编码方式与字节序 |
| A7 | 序列号 | 序列号规则(请求-响应匹配) |
| A8 | 校验算法 | CRC/校验和算法与多项式 |
| A9 | ACK 与重试 | 应答机制、重试次数、退避策略 |
| A10 | 超时规则 | 各命令超时时间 |
| A11 | 分包与组包 | MTU 内分片与重组规则 |
| A12 | 错误码 | 设备端错误码表 |
| A13 | 设备状态机 | 状态定义与合法迁移图 |
| A14 | 协议版本号 | 版本协商机制与兼容策略 |

## B. 设备命令(必须,至少包括)

获取 SN;获取型号;获取固件版本;获取电量;获取剩余空间;获取录音状态;获取录音模式;获取文件列表;开始录音;暂停;停止并保存;修改录音参数;开启 Wi-Fi 传输;删除文件;恢复出厂;重启;进入 OTA 模式。

每条命令需提供:请求/响应帧格式、参数取值范围、错误码、执行时长上限。

## C. Wi-Fi 文件传输协议(必须)

| # | 项目 | 说明 |
|---|---|---|
| C1 | 网络模式 | SoftAP / Wi-Fi Direct / 局域网,三选一并说明 |
| C2 | SSID 与密码生成 | 生成规则(是否含 SN、是否随机、有效期) |
| C3 | App 自动加入方式 | 与 iOS NEHotspotConfiguration / Android P2P 的兼容性说明 |
| C4 | 文件列表 API | 端点、分页、字段定义 |
| C5 | 文件大小 | 索引中是否含精确字节数 |
| C6 | 文件时间 | 时间戳来源与时区(RTC 校准机制) |
| C7 | 音频格式 | 编码、采样率、声道、容器格式,按录音模式列全 |
| C8 | Range 断点续传 | 是否支持 HTTP Range 或等价机制 |
| C9 | 文件校验 | MD5 或 SHA-256,由设备提供还是 App 计算比对 |
| C10 | 下载完成确认 | 确认命令与设备侧标记 |
| C11 | 设备端文件删除 | 删除命令与安全确认 |
| C12 | 传输中断恢复 | 设备热点超时/断开后的恢复行为 |
| C13 | 手机同时访问互联网 | 双网并存能力或切换策略说明 |
| C14 | 并发限制 | 是否允许多连接、多手机同时访问的行为定义 |

## D. OTA 协议(必须)

| # | 项目 | 说明 |
|---|---|---|
| D1 | 固件包签名 | 签名算法与验签流程 |
| D2 | 固件版本 | 版本号格式与读取命令 |
| D3 | 硬件型号限制 | 固件与型号匹配校验 |
| D4 | 升级前电量判断 | 最低电量阈值 |
| D5 | 分包传输 | 包大小、顺序、丢包重传 |
| D6 | 进度查询 | 进度上报机制 |
| D7 | 校验 | 完整性校验(整包 + 分包) |
| D8 | 双分区或失败恢复 | 变砖防护机制说明 |
| D9 | 禁止降级策略 | 是否允许降级及控制方式 |
| D10 | App 最低版本限制 | 固件对 App 版本的要求字段 |

## E. 交付物与授权(立项红线)

1. 完整协议文档(A—D 全部);
2. **6 台以上工程样机**;
3. BLE 调试工具(PC 或手机端);
4. 固件工程师对接人(姓名、响应 SLA);
5. 固件修改能力(可按协议缺陷清单迭代);
6. OTA 升级能力(测试通道);
7. **协议和 App 独立使用授权**(书面,写入采购合同)。

## F. 合同必备条款

- 协议必须写入采购合同;App 与协议使用权归我方;
- 固件源代码托管,或至少长期维护承诺;
- 协议变更提前通知期;严重问题响应时间;
- 预留替换硬件方案商的能力(协议可移植性)。

## G. 判定标准(第 5 天技术评审,四选一)

1. **可以自主开发** — A—E 齐全,双平台抓包验证通过;
2. **需要硬件厂修改** — 输出协议缺陷清单,约定修改排期后再评审;
3. **只能换皮** — 仅有 APK/IPA/封闭 SDK,无底层协议与固件配合 → 不能按"自主研发 App"立项;
4. **建议更换方案商**。

阶段0 退出标准:iOS 和 Android 都可发现设备、读取文件、下载完整文件并校验;固件团队确认可修改协议;协议无不可控授权问题。**不满足即暂停 App 全面研发。**
