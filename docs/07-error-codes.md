# 错误码体系 V1.0

- 客户端(Flutter/原生)与服务端共用一套编号;服务端实现:`server/app/core/errors.py`(唯一事实来源,本文档与代码同步修改)。
- 格式:`<域前缀>_<四位数字>`。前两位为子域,后两位为具体错误。
- 每个错误码定义:是否可自动重试(retryable)、是否面向用户展示(user_facing)、建议文案 key(i18n)。
- 埋点:所有错误码触发均上报 `error_occurred` 事件(见 `08-analytics-plan.md`),管理后台 `/admin/errors` 按码聚合。

| AUTH_0001 | 验证码错误或过期 | 否 | 提示重新获取 |

| AUTH_0003 | Token 过期 | 是 | 静默 refresh,失败转登录 |
| AUTH_0004 | Refresh token 失效 | 否 | 强制重新登录 |
| AUTH_0005 | 三方登录凭证无效 | 否 | 提示重试 |
| AUTH_0006 | 账户已在注销冷静期 | 否 | 提示可撤销注销 |
| AUTH_0007 | 账户被封禁 | 否 | 联系客服 |
| AUTH_0008 | 验证码尝试次数超限 | 否 | 引导重新获取验证码 |

## 客户端处理约定

1. `retryable=true`:指数退避(2s/4s/8s,上限 3 次)后仍失败才展示错误。
2. 展示文案一律走 i18n key(`error.<code>`),三语齐备;未定义 key 回落到通用文案 + 错误码展示。
3. 任何错误展示必须带错误码尾缀(便于客服定位),例:`同步失败,请重试 (DEV_1204)`。
4. `JOB_4001` 与 `ORD_5004` 属于程序缺陷类,触发即告警,不静默。
