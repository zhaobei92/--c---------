# memory-bench — 项目宪法

> 本文件是项目的最高约束。任何取舍与本文件冲突时，以本文件为准；
> 需要偏离时，必须先取得项目所有者的明确同意，并把偏离与理由写进 `PROGRESS.md`。

## 这是什么

这是一个技术选型调研项目，不是产品开发。目标：实测对比多个开源 agent 记忆框架，
产出选型报告，为后续"记忆系统"产品（通用核心 + 养老/宠物/机器人等专用适配）
提供选型依据。

**禁止在本项目中开发任何产品功能。具体做什么以 `TASK.md` 为准。**

## 硬性约束

1. **优先本地运行**：转写、向量化、LLM 推理优先用本机 GPU 跑开源模型；若本机算力
   不足或环境未就绪，停下来问项目所有者是否允许临时用外部 API，并单独记录由此
   产生的成本数字。
2. **不动本项目目录以外的任何东西。**
3. **每个框架独立虚拟环境**（venv/conda），依赖互不污染；所有安装命令写进各自的
   `setup.sh`。
4. **分阶段执行**：每个阶段先出计划，等项目所有者批准再动手。
5. **诚实记录失败**：某框架装不上、跑不通、文档造假，都是有效调研结论，如实写进
   报告，不许硬凑数据、不许降低测试标准来让它通过。

## 验收标准

- `results/` 下有统一格式的原始数据和汇总对比表（CSV 或 JSON）
- `report.md` 选型报告：结论先行，每个框架的实测指标 + 明确推荐 + 理由 + 风险
- 项目所有者能按 `README.md` 一步步复现任意一项测试

## 工作方式

- 进度实时写入 `PROGRESS.md`，每完成一个框架更新一次
- 会话中断后，读 `PROGRESS.md` 恢复上下文接着干，不重做已完成的部分
