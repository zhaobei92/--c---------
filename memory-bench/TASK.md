# 任务书：开源记忆框架实测对比（memory-bench）

## 待测框架（按优先级）

1. **Mem0** — github.com/mem0ai/mem0（即插即用记忆层）
2. **Letta** — github.com/letta-ai/letta（操作系统式分层记忆）
3. **Graphiti** — github.com/getzep/graphiti（时序知识图谱：每条事实带生效/失效时间窗）
4. **Memvid** — 零基础设施、面向离线/边缘的方案
5. **（加分项，时间允许再测）Hindsight**

以 GitHub 当前实际状态为准；如某项目已停维护或安装严重受阻，记录原因后跳过，不硬耗。

## 测试数据

- `data/` 目录下若有文件：那是真实对话转写文本（含时间信息），直接使用。
- 若 `data/` 为空：先生成模拟数据顶上——3 个场景 × 各覆盖 30 天：
  1. 养老院长者日常对话（含用药、身体不适、家属探视）
  2. 宠物主人日常（喂食、行为、就医）
  3. 机器人任务日志（人、物、地点、任务）

  数据必须包含随时间变化的事实（如用药方案第 10 天调整）。报告中明确标注
  "基于模拟数据"，真实数据到位后重测关键项。

## 统一测试流程（每个框架完全相同）

1. 独立环境安装，跑通官方最小示例；记录安装耗时、依赖体积、踩坑
2. 灌入同一份测试数据
3. 跑同一套问题集 `question_set.json`（阶段1先生成，覆盖以下五类、每类不少于 10 题，
   附标准答案，交项目所有者确认后冻结）：
   - 事实回忆：某人某天说过什么
   - 时间定位："上周三下午聊了什么"
   - 事实变更："现在的用药方案是什么"（考察新旧事实覆盖）
   - 跨会话综合：需要拼多天信息才能答的问题
   - 拒答/防编造：数据里不存在的事，看它会不会瞎编
4. 每框架记录指标：
   - **准确率**：逐题对错判定，输出人工可核对的对照表（问题/标准答案/框架回答/判定）
   - **检索延迟**：P50 / P95（即 50% 和 95% 的查询在多少毫秒内返回）
   - **token 消耗**：灌入阶段总消耗 + 单次查询平均消耗
   - **资源占用**：内存 / 显存峰值
   - **端侧可行性**：依赖分析——能否在 Jetson（ARM64、8–16GB 内存）上安装运行；
     不实机测，给出依赖层面的结论和最低配置估计

## 附加评估（查资料 + 读源码即可，写进报告）

- 记忆表示方式（向量 / 图 / 文件）及可解释性：出了错能不能定位到是哪条记忆的问题
- 多模态扩展性：图像、位置、传感器数据能否纳入记忆
- License、自托管成熟度、社区活跃度（近 90 天 commit / issue 响应）
- 与"通用核心 + 专用 schema"架构的适配度：加自定义字段（用药记录、宠物行为标签）的难易

## 产出

- `results/`：原始日志 + 汇总对比表
- `report.md`：选型报告，结论先行——推荐谁做通用核心、谁适合端侧、各自风险与规避
- `README.md`：环境要求 + 复现步骤
- `question_set.json` + 数据生成脚本

## 执行流程

- **阶段1**：出测试方案 + `question_set.json` → 项目所有者批准
- **阶段2**：逐框架执行（每完成一个更新 `PROGRESS.md`）
- **阶段3**：汇总写报告 → 交付
