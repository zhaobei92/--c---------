### 基线实测结果（BM25，非框架，仅作下限参照）

在本机（4 核 CPU、无 GPU、无网络）跑完 60 题：

| 指标 | 数值 |
|---|---|
| 自动判定准确率 | 29/60 = **48.3%** |
| ├ fact_recall | 10/12 = 83% |
| ├ temporal_locate | 8/12 = 67% |
| ├ cross_session | 7/12 = 58% |
| ├ fact_change | 4/12 = 33% |
| └ refusal | **0/12 = 0%** |
| 检索延迟 P50 / P95 | 0.7 ms / 0.99 ms |
| 灌入 token（3 场景合计） | 10,790 |
| 单次查询平均 token in/out | 16.8 / 223.9 |
| 内存峰值 | 16.3 MB |

抽查确认这是真实表现而非判分器 bug：

- **拒答 0/12** 是纯检索的先天缺陷——BM25 总能捞到分数过阈的闲聊（问"糖尿病用药"
  返回的是"电视里讲老北京胡同"），没有生成环节就没有弃权能力。
- **fact_change 4/12** 典型失败样式：问"书法班现在周几"，它把含"周三"的旧记录
  原样吐出来，被判"把旧值当现行事实"。

弃权阈值 `SCORE_FLOOR = 1.0` 是先验设定，**没有针对问题集调过**——调它能美化
拒答分数，属于宪法第 5 条禁止的凑数据。
